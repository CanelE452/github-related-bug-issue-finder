## 실제 중복 쌍 평가 — 매우 작은 표본

GitHub의 [#47332 종료 상태](https://github.com/huggingface/transformers/issues/47332)에 명시된 원본 #47333을 정답으로 사용했습니다. 입력 Issue 자체는 후보에서 제외했습니다.

| 방식 | 쌍 수 | 정답 순위 | Recall@1 | Recall@5 | MRR |
|---|---:|---:|---:|---:|---:|
| BM25 | 1 | 1 | 1.0 | 1.0 | 1.0 |
| Semantic | 1 | 1 | 1.0 | 1.0 | 1.0 |
| Hybrid | 1 | 1 | 1.0 | 1.0 | 1.0 |

**이 숫자는 성능 우열이나 일반적인 정확도의 근거가 아닙니다.** 실제 출처가 있는 데이터로 평가 도구가 동작하는지 확인하는 탐색적 결과입니다. 그룹이 1개여서 검증 split은 0개, test split은 1개입니다. 튜닝이나 학습은 수행하지 않았습니다.

원본 결과: `evaluation/output/verified-test.json`, `evaluation/output/verified-test.csv`. 재현 명령은 `docs/evaluation.md`에 있습니다. 로컬 스냅샷과 출력 파일은 Git에서 제외되므로 다른 PC에서는 같은 원본 데이터도 함께 보존해야 정확히 재현됩니다.

## 검색 관찰

- 한국어 문제 `음성 생성 파이프라인에서 dtype 인자를 지원하지 않는다는 오류가 발생해요.`만 입력한 Hybrid 검색에서 실제 관련 문서 #48732와 #48683이 각각 1·2위로 나왔습니다.
- 메모리 부족처럼 포괄적인 문제에서는 검색 방식별 결과가 크게 달랐습니다. 장문 환경 정보와 공통 GPU 키워드가 순위에 영향을 줄 수 있으며, 현재 결과만으로 Hybrid가 항상 낫다고 주장하지 않습니다.
- 자체 생성한 `[PROBLEM]` 같은 입력 구분자가 BM25 검색어에 섞이지 않도록 수정했습니다. 사용자 로그의 경로·숫자를 정규화한 것은 아닙니다.
- warm 상태의 짧은 질의는 이 실행에서 약 0.08~0.32초였으나, 재시작 직후 모델 로딩 대기는 약 19초를 포함했습니다. 장문 질의와 하드웨어에 따라 시간이 달라집니다.

## 남은 데이터 제약

1. PyTorch 저장소 조사는 GitHub 비인증 API 호출 제한으로 완료하지 못했습니다. 토큰 설정 또는 제한 해제 후 `evaluation.survey`를 다시 실행해야 합니다. 두 저장소의 유효 쌍 수를 비교한 최종 선택은 아직 아닙니다.
2. transformers의 이번 수집 범위에는 duplicate 레이블 후보가 없었습니다. `state_reason=duplicate` 후보 3개도 지원하도록 수집기를 보완했으며, 자동 timeline 조사는 API 제한 해제 후 다시 실행해야 합니다. 위 평가 쌍은 공개 GitHub 종료 배너에서 별도로 확인했습니다.
3. 사람이 검토한 한국어 평가 문항이 아직 없으므로 한국어 Recall/MRR는 제시하지 않습니다. 한국어 기능 점검 결과와 구분합니다.
4. 신뢰할 만한 비교 실험에는 더 많은 검증된 중복 쌍과 저장소 다양성이 필요합니다.

서비스·평가 코드와 로컬 실행 환경은 준비되었으며, 본격적인 성능 검증에는 위 데이터 보강이 필요합니다.
